# Snow-World 구현 기록지

## 1. 프로젝트 개요

- **프로젝트명:** Snow-World
- **목표:** macOS 데스크탑에 겨울 풍경과 눈 내림을 표시하고, 화면의 창·Dock·데스크탑 아이콘 위에 눈이 쌓여 중력에 따라 움직이는 인터랙티브 앱을 만든다.
- **실행 환경:** 사용자의 Mac에서 단독 실행
- **서버:** 사용하지 않음
- **권장 기술:** Swift, SwiftUI, AppKit, ScreenCaptureKit, Accessibility API
- **초기 브랜치:** `dev`

로그인, 계정, 원격 API, 데이터 동기화는 범위에 넣지 않는다. 설정과 게임 상태는 로컬에 저장한다. 화면 정보도 필요한 처리를 마친 뒤 기기 밖으로 보내지 않는다.

## 2. 핵심 구현 결정

### 2.1 프레임마다 화면을 분석하지 않는다

화면을 매 프레임 캡처해 인식하면 CPU/GPU 사용량과 배터리 소모가 커지고, 창의 그림자·투명도·애니메이션 때문에 표면 검출이 흔들릴 수 있다. 따라서 역할을 두 흐름으로 분리한다.

1. **화면 구조 갱신:** 창 이동/크기 변경, 디스플레이 구성 변경, Dock 이동 등 구조가 바뀌었을 때만 표면 정보를 다시 가져온다.
2. **눈 시뮬레이션:** 화면 구조를 다시 읽지 않고, 눈의 위치·속도·쌓인 높이를 목표 프레임률로 갱신해 그린다.

접근성 알림을 받을 수 없는 변화나 알림 누락에 대비해 저빈도 보정 타이머(예: 1~2초 간격)를 둔다. 이 타이머는 화면 전체 이미지 분석이 아니라 창/접근성 메타데이터를 재조회하는 용도다. 실제 간격은 프로파일링 후 조정한다.

### 2.2 화면 캡처는 보조 수단으로 제한한다

창 위치·크기 같은 정보는 먼저 Accessibility API와 AppKit의 화면/창 메타데이터에서 얻는다. 접근성 정보로 모양을 얻을 수 없는 창에만 ScreenCaptureKit 프레임을 제한적으로 사용해 가시 영역을 보정한다. 픽셀 분석은 저해상도·저빈도·변경 영역 중심으로 수행한다. 전체 화면을 매 프레임 스캔하는 구조는 사용하지 않는다.

화면을 캡처하는 기능을 켤 때는 macOS 화면 기록 권한이 필요할 수 있다. 권한이 없거나 사용자가 거부한 경우 앱은 메타데이터만으로 동작하고, 화면 캡처 기반 보정 기능을 비활성화한다. 권한 상태와 캡처 대상은 설정 화면에 알기 쉽게 표시한다.

### 2.3 인식 결과는 확신도와 출처를 가진 표면으로 관리한다

모든 물체를 완벽하게 복원하려고 하지 않는다. 눈이 쌓일 수 있는 경계를 짧은 선분과 간단한 폴리곤으로 근사하고, 출처·확신도·갱신 시각을 함께 관리한다. 신뢰도가 낮은 표면은 눈 충돌 대상으로 사용하지 않거나 빠르게 만료한다.

## 3. 기능 범위

### 첫 MVP

- 4K 겨울 배경 표시 및 디스플레이 크기에 맞춘 배율 조정
- 여러 디스플레이 지원의 기본 구조
- 자연스러운 눈 입자 애니메이션
- 화면 하단과 앱 오버레이 안의 단순 표면에 눈 쌓임
- 마우스로 눈을 밀고, 모아 굴리는 기본 상호작용
- 설정 창: 눈 양, 속도, 일시정지, 오버레이 켜기/끄기
- 서버 없이 로컬 설정 저장

### 후속 기능

- 창의 윗면·기울어진 면 인식 및 눈 쌓임
- Dock 표면 추적
- 데스크탑 파일/폴더 아이콘 표면 추적
- 눈이 경사면을 타고 이동하거나 가장자리에서 떨어지는 효과
- 눈덩이 세 개를 크기 순서로 쌓아 눈사람 완성
- 산타와 루돌프의 간헐적 썰매 비행 이벤트
- 로그인 시 자동 실행, 앱 메뉴바 제어

후속 기능은 API 권한과 인식 정확도 검증 결과에 따라 범위를 확정한다. 특히 데스크탑 아이콘 위치 정보는 Finder/접근성 트리에서 안정적으로 제공되지 않을 수 있으므로, 초기에 기술 검증을 통과하지 못하면 아이콘 위치를 사용자가 지정하는 대체 방식을 제공한다.

## 4. 앱 아키텍처

```text
SnowWorldApp (SwiftUI 설정/메뉴바)
  ├─ DesktopSceneController (AppKit 창 수명주기, 모니터별 장면)
  ├─ ScreenTopologyService (디스플레이/창/Dock 메타데이터)
  ├─ AccessibilitySurfaceProvider (접근성 요소 수집)
  ├─ OptionalCaptureProvider (선택적 ScreenCaptureKit 보정)
  ├─ SurfaceModel (충돌 경계와 확신도)
  ├─ SnowSimulation (입자, 적설 높이, 눈덩이, 중력)
  ├─ SnowRenderer (Metal 우선, MVP는 Core Animation/Canvas 평가)
  ├─ SantaEventController (이벤트 스케줄과 경로)
  └─ LocalSettingsStore (UserDefaults/AppStorage)
```

### 컴포넌트 책임

- **SnowWorldApp:** 메뉴바와 설정 UI, 권한 상태 및 시뮬레이션 제어.
- **DesktopSceneController:** 각 디스플레이에 맞는 투명/배경 창을 만들고 화면 구성 변경을 반영.
- **ScreenTopologyService:** NSScreen 정보와 접근 가능한 창 메타데이터를 관찰하고 구조 변경 이벤트를 전달.
- **AccessibilitySurfaceProvider:** 창과 Finder 요소의 프레임 등 가능한 접근성 정보를 읽는다. 접근성 권한이 없으면 비활성화.
- **OptionalCaptureProvider:** 사용자가 허용한 경우에만 캡처 프레임에서 접근성 데이터가 부족한 표면을 저빈도로 보정.
- **SurfaceModel:** 서로 다른 좌표계의 결과를 하나의 논리 좌표계로 변환하고 단순 충돌 지형으로 제공.
- **SnowSimulation:** 고정 시간 간격으로 물리를 계산. 렌더링 프레임 수와 물리 결과가 달라지지 않도록 시간 누적기를 쓴다.
- **SnowRenderer:** 시뮬레이션 상태를 화면에 표현. 설정 UI와 렌더 루프는 분리한다.
- **LocalSettingsStore:** 배경, 눈 강도, 프레임 상한, 이벤트 빈도, 대상 표면 설정 저장.

## 5. 화면 표면 수집

### 5.1 대상 우선순위

1. 각 디스플레이의 화면 경계 및 하단 지형
2. Snow-World가 소유한 배경 장면의 지붕·난간·나뭇가지처럼 앱이 직접 정의한 표면
3. 위치를 조회할 수 있는 다른 앱 창의 윗변과 좌우 경계
4. Dock의 외곽 경계
5. Finder가 제공하는 데스크탑 아이콘의 접근성 프레임
6. 앞선 정보만으로 불가능한 범위에 대한 선택적 캡처 보정

### 5.2 갱신 이벤트

- 디스플레이 추가/제거, 해상도·배율·회전 변경
- 창 생성/닫기/이동/크기 조정/앞뒤 순서 변경
- Dock의 위치 또는 크기 변경을 확인할 수 있는 시스템 이벤트
- Finder 데스크탑 요소 트리 변경 알림(사용 가능한 경우)
- 앱 복귀, 권한 변경, 잠자기/깨우기

알림마다 전체 지형을 무조건 다시 만드는 대신 변경된 표면만 교체한다. 저빈도 전체 메타데이터 재조회로 이벤트 누락을 보정한다. 창이 최소화되거나 화면 밖으로 이동하면 표면을 제거하거나 비활성화한다.

### 5.3 표면 데이터 구조

```swift
struct SurfaceSegment: Identifiable {
    let id: UUID
    let start: CGPoint
    let end: CGPoint
    let normal: CGVector
    let kind: SurfaceKind
    let confidence: Float
    let sourceID: String
    let updatedAt: ContinuousClock.Instant
}
```

`SurfaceKind` 예: `screenEdge`, `windowTop`, `dock`, `desktopIcon`, `sceneStatic`, `userPinned`.

표면은 화면 좌표계(좌하단 원점 등 하나로 통일)로 변환한다. Retina 배율과 디스플레이별 원점/회전 차이를 고려하고, 변환 결과는 테스트 가능한 순수 함수로 둔다.

## 6. 오버레이와 입력 처리

- 디스플레이별로 화면 크기에 맞는 장면 창을 관리한다.
- 눈 시각화 레이어는 투명하게 구성하고, 평소에는 마우스 이벤트를 아래 앱으로 전달한다.
- 눈을 조작할 때만 포인터 주변의 짧은 입력 구간을 받아 눈을 밀거나 굴린다. 모든 화면 입력을 가로채지 않는다.
- 배경화면 모드와 화면 전체 눈 오버레이 모드를 분리한다. 전체 화면 오버레이는 클릭 통과, 포커스 획득 방지, Dock/메뉴바 가림 여부를 실기기에서 검증한다.
- 창 모드 전환 시 포커스, Mission Control, 전체 화면 앱, 메뉴바, Dock과의 호환성을 확인한다.

## 7. 눈 물리 시뮬레이션

### 7.1 적설 표현

표면별로 일정 간격의 높이 샘플을 둔다. 각 샘플은 누적된 눈 높이와 밀도/질량 근사값을 가진다. 입자가 표면에 닿으면 충돌 위치 주변 샘플에 눈을 더한다. 매 입자를 영구 물체로 보존하지 않아 메모리 증가를 막는다.

### 7.2 입자 업데이트

- 중력, 초기 수평 바람, 크기와 질량에 따른 낙하 속도 변화를 적용한다.
- 고정 시간 간격(예: 1/60초 또는 1/120초)으로 물리를 계산하고, 렌더링은 기기 성능에 맞춰 최대 프레임을 제한한다.
- 화면 밖 입자는 제거하고, 적설 상태는 표면별 높이 필드로 유지한다.
- 과부하 시 입자 수와 렌더 세부도를 낮춘다. 적설 지형의 안정성은 유지한다.

### 7.3 경사면, 붕괴와 낙하

- 인접 높이 차와 표면 법선으로 국소 경사를 계산한다.
- 안정 경사 임계값을 넘는 눈은 낮은 쪽 샘플로 이동한다.
- 한 번에 이동하는 양을 제한해 눈이 갑자기 튀지 않도록 한다.
- 표면 끝을 넘어간 눈은 아래 표면을 찾아 새 충돌 대상으로 재투입한다.
- 아래 표면을 찾지 못하면 화면 밖으로 사라진다.
- 고정 배경의 나뭇가지나 지붕은 아티스트가 제공한 충돌 경계를 사용할 수 있다.

### 7.4 마우스 인터랙션과 눈사람

- 포인터 주변에 부드러운 힘장을 적용해 눈을 밀어낸다.
- 길게 드래그하면 일정량의 눈을 모아 굴릴 수 있고, 눈덩이 반경은 모인 질량에 따라 커진다.
- 완성용 눈덩이 세 개의 반경 범위를 정의한다. 작은 공·중간 공·큰 공을 가까이 두고 일정 시간 안정적으로 접촉하면 눈사람으로 조립한다.
- 눈사람에는 눈·코·팔 장식을 단계적으로 표시한다. 장식은 첫 버전에서 자동 생성해도 되며 설정에서 꾸미기 기능은 후속으로 둔다.
- 완성된 눈사람은 고정 개체로 남고, 사용자가 밀거나 초기화할 수 있다.

## 8. 산타·루돌프 이벤트

- 로컬 타이머가 사용 시간과 설정된 빈도를 기준으로 이벤트를 시작한다.
- 화면 밖 시작/종료 지점을 사용하고, 곡선 경로와 미세한 흔들림을 줘 하늘을 가로질러 비행시킨다.
- 창 표면 정보 수집과 별도 모듈로 운용한다.
- 눈 입자와 겹치는 경우 시각적 파티클만 추가한다. 산타 썰매를 물리 충돌 표면으로 취급할지는 후속 선택 사항.
- 배터리 절약/일시정지 상태, 전체 화면 앱, 방해 금지 설정을 존중하는 옵션을 둔다.

## 9. 권한과 개인정보

- **접근성 권한:** 다른 앱 창과 Finder 요소의 위치를 읽는 기능에 필요할 수 있다. 사용자가 허용하지 않아도 기본 눈 배경은 동작해야 한다.
- **화면 기록 권한:** 픽셀 기반 보정에 필요한 경우에만 요청한다. 기본 실행 시 강제로 요구하지 않는다.
- 캡처 이미지 프레임은 로컬 메모리에서 분석한 뒤 저장하거나 외부 전송하지 않는다.
- 서버, 분석 SDK, 광고 SDK, 로그인, 네트워크 통신을 넣지 않는다.
- 권한 목적과 기능 저하 범위를 설정 화면과 첫 실행 안내에서 설명한다.

## 10. 성능과 안정성 목표

- 기본 동작은 눈 애니메이션이 부드럽고 입력 지연이 낮아야 한다.
- 화면 구조 갱신과 물리 루프를 분리해 창 위치 재조회가 렌더 프레임을 막지 않도록 한다.
- 시뮬레이션 업데이트는 단일 직렬 큐/Actor에서 처리하고, 렌더러에는 불변 스냅샷을 전달한다.
- 입자 수, 표면 수, 화면 수 상한을 설정해 최악의 경우에도 메모리와 CPU/GPU 사용량을 통제한다.
- 디스플레이 연결/해제, 앱 재시작, 권한 철회, 잠자기/깨우기 후 상태를 복구한다.
- 접근성 트리가 응답하지 않거나 캡처 세션이 실패해도 앱 전체가 종료되지 않도록 해당 공급자만 재시작한다.

## 11. 구현 단계와 완료 조건

### 단계 0 — 저장소와 기본 앱

- SwiftUI macOS 앱 타깃과 실행 구조 확정
- `dev`에서 페이지/기능별 작은 이슈로 진행
- README에 요구 macOS 버전, 실행법, 권한 설명 기록
- **완료:** 맥에서 빌드·실행되고 메뉴바/설정 창이 열린다.

### 단계 1 — 4K 배경과 눈 애니메이션

- 배경 이미지 에셋 추가
- 한 디스플레이에서 눈 입자 렌더링 및 프레임 제한
- 일시정지/강도 설정
- **완료:** 해상도와 배율이 달라도 장면이 맞고, 성능 설정이 동작한다.

### 단계 2 — 로컬 눈 적설과 마우스

- 화면 하단/장면 배경의 표면 높이 필드
- 충돌, 누적, 마우스 밀기와 눈덩이 굴리기
- **완료:** 눈이 바닥에 쌓이며 마우스로 움직이고, 재실행 시 설정이 복원된다.

### 단계 3 — 화면/창 표면 기술 검증

- 권한 안내와 Accessibility API 프로토타입
- 창 프레임과 이벤트 갱신 가능 범위 기록
- Finder 데스크탑 아이콘 정보 접근 가능성 별도 검증
- Dock 위치/프레임을 얻는 시스템 경로 조사 및 실기기 시험
- **완료:** 지원 가능한 표면 종류, 필요한 권한, 정확도, 실패 대체 동작을 문서화한다.

### 단계 4 — 창·Dock 표면 적설

- 얻은 프레임을 표면 선분으로 변환
- 창 이동/크기 변경에 따라 표면을 갱신
- 눈이 표면에 쌓이고 가장자리에서 떨어지는 동작
- **완료:** 창을 움직여도 눈 지형이 일정 시간 안에 새 위치로 따라가고, 낮은 확신도 결과는 오작동하지 않는다.

### 단계 5 — 데스크탑 아이콘, 눈사람, 이벤트

- Finder 요소 인식 또는 사용자가 직접 표면을 지정하는 대체 UI
- 눈덩이 3개를 결합해 눈사람 생성
- 산타·루돌프 이벤트 스케줄과 애니메이션
- **완료:** 권한이 없는 조건에서도 기본 앱이 유지되고, 이벤트와 상호작용을 설정에서 끌 수 있다.

### 단계 6 — 다중 디스플레이와 배포 준비

- 모니터별 장면과 좌표계 변환
- 해상도/배율 변경, 잠자기/깨우기, 전체 화면 앱 호환성
- 앱 서명·배포 방식 및 사용자 안내
- **완료:** 다중 모니터 연결 변경 시 복구되고, 권한 및 성능 한계가 사용자 문서에 명시된다.

## 12. 검증 항목

- 창 이동/크기 변경/최소화/전체 화면 후 표면이 갱신되는지
- Dock을 좌우/하단으로 이동했을 때 위치가 반영되는지
- Finder 아이콘의 프레임을 권한별로 확인할 수 있는지
- Retina 배율, 서로 다른 해상도·회전·다중 디스플레이에서 좌표가 맞는지
- 화면 기록/접근성 권한 거부 및 앱 실행 중 철회 시 안정성
- 마우스 이벤트가 앱 클릭을 막지 않는지
- 입자 최대치와 장시간 실행에서 CPU/GPU/메모리 추이
- 잠자기/깨우기, Mission Control, 전체 화면 앱과의 충돌
- 눈사람을 만드는 조건이 일관되고 잘못된 접촉으로 완성되지 않는지
- 서버 연결 없이 모든 핵심 기능이 동작하는지

## 13. 주요 위험과 대응

| 위험 | 이유 | 대응 |
|---|---|---|
| 앱 창의 실제 보이는 모양과 접근성 프레임 불일치 | 그림자, 모서리, 투명 창이 메타데이터 경계와 다름 | 초기에는 상단/주요 경계만 사용하고 불확실한 모양은 생략 |
| Finder 아이콘 프레임 접근 불가 | Finder 접근성 트리가 아이콘 배치를 안정적으로 제공하지 않을 수 있음 | 단계 3에서 먼저 검증하고, 실패 시 사용자가 표면을 핀으로 지정 |
| Dock 메타데이터 접근 제한 | Dock은 별도 프로세스와 시스템 설정의 영향을 받음 | 공개 API로 접근 가능한 경로부터 검증, 불가하면 화면 가장자리 기본 표면 사용 |
| 화면 기록 권한 거부 | 픽셀 보정 기능을 사용할 수 없음 | 권한 없이도 기본 모드 제공, 보조 보정만 비활성화 |
| 과도한 프레임 분석 비용 | 배터리·발열·성능 저하 | 이벤트 중심 메타데이터 갱신, 제한된 캡처 보정, 품질 단계 조절 |
| 클릭을 가로채는 오버레이 | 사용성 저하 | 기본 클릭 통과, 드래그 조작 구간만 선택적으로 입력 처리 |

## 15. 첫 기술 검증에서 답해야 할 질문

1. 지원할 최소 macOS 버전을 어디로 잡을지.
2. Accessibility API가 다른 앱 창 프레임과 Finder 아이콘 프레임을 어떤 권한 조건에서 제공하는지.
3. 창 이벤트를 이벤트 기반으로 받을 수 있는 범위와 저빈도 보정 주기.
4. Dock 위치·크기 정보를 공개 API로 얻을 수 있는지.
5. 화면 전체 투명 창이 클릭 통과와 다중 디스플레이에서 안정적으로 동작하는지.
6. 성능 목표에 맞는 렌더러가 Core Animation/Canvas인지 Metal인지.

이 질문은 코드에 앞서 전부 확정할 필요는 없다. 단계 1~2의 시각 프로토타입을 진행하면서 단계 3에서 macOS 실기기 검증으로 답을 얻는다.

## 16. 구현 진행 기록

### 2026-11-21 — 0.1.0 화면 프로토타입 착수

- Tuist 프로젝트와 macOS 13.0 앱 타깃을 구성했다.
- SwiftUI 창과 메뉴 막대 메뉴를 추가했다.
- 겨울 산장 장면, 타임라인 기반 눈 입자, 하단 눈 드리프트를 첫 화면에 배치했다.
- 눈 내림, 강도, 적설 표시 설정을 `UserDefaults`에 로컬 저장하도록 구성했다.
- 배경 에셋은 3840×2160 JPEG로 포함했다. 현재 원본 생성 이미지(1672×941)를 고품질 리사이즈한 것이므로, 진짜 4K 원본 디테일은 후속 아트 작업에서 교체할 수 있다.
- 이 단계는 앱 창 안에서 미리 보는 프로토타입이다. 다른 앱/Dock/폴더 위에 뜨는 투명 오버레이와 화면 요소 인식은 아직 구현하지 않았다.
- 검증 한계: 작업 환경에 Xcode와 Swift 컴파일러가 없어 macOS 빌드/실행은 확인하지 못했다. Mac에서 `tuist generate` 후 Xcode 빌드가 필요하다.
